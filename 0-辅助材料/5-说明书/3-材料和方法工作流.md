# 材料和方法（M&M）工作流说明书

> 论文「材料和方法」章节的笔记化流水线。两趟 AI 交互：第一趟抽方法名+变体、第二趟补定义+分类。 本文档面向作者本人，记录每步的按钮、stepId、配置键、文件夹位置、数据流。

---

## 一、文件夹与配置键总览

目录配置在 runner.py 的 `_REL_FOLDER_DEFAULTS`，相对 Vault 根，运行时自动拼绝对路径。

### 笔记产出目录

|配置键|默认路径|存什么|
|---|---|---|
|`methods_category_notes_dir`|`2-文献摘抄/3-方法笔记/1-方法总类`|大分类笔记（双链索引各具体方法）|
|`methods_method_notes_dir`|`2-文献摘抄/3-方法笔记/2-具体方法`|具体方法笔记（每方法一笔记）|

### 指令 / 辞典 / 中转站文件（在 App 文件设置里指定）

|配置键|所在 App 文件夹|用途|
|---|---|---|
|`methods_extract_prompt`|1-AI指令|方法归类指令（第一趟）|
|`methods_def_prompt`|1-AI指令|方法定义指令（第二趟）|
|`methods_dictionary_file`|2-辞典|方法辞典（具体方法+变体+定义+研究目的+大分类+已参考PMID）|
|`methods_ai_result`|3-中转站|第一趟 AI 结果（方法名+变体+原文）|
|`methods_def_ai_result`|3-中转站|第二趟 AI 结果（定义四列表）|

### 共用

|配置键|用途|
|---|---|
|`待分析文献文件夹`|`1-文献输入/1-文献原文`，回写原文时按 PMID 定位源笔记|

## 二、第一趟：抽方法名 + 变体

### 步骤 1｜拼接　`methods_assemble`（备选手选：`methods_assemble_manual`）

- 读已参考 PMID（方法辞典「已参考·材料和方法」）→ 扫各论文 M&M 章节（按辞典里的标题变体识别）→ 拼「方法归类指令 + M&M 原文 + 辞典（具体方法与变体）」→ 剪贴板。
- 贴给 AI。AI 就地标 `### 方法名` / 变体行，新方法、新变体加 `**[待审]**`，输出到 `methods_ai_result`。
- 手选模式：从手选中转站文件读论文（`manual_transit_file`），其余同。

> 第一趟只标方法名和变体，**不写定义、不写分类**（留第二趟）。

### 步骤 2｜笔记创建分发　`methods_apply`

- 解析 `methods_ai_result`（`### 方法名` + 变体行 + 原文）。
    - 旧方法 → 直接分发（不重复建）。
    - 新方法（已**解除** `[待审]`）→ 创建具体方法笔记（→ `methods_method_notes_dir`）+ 写入辞典（方法名/变体，定义等列留空）。
    - 仍带 `**[待审]**` 的 → 逐条跳过（等你人工审核解除）。
- **不碰**源论文 / YAML / 已参考 / 大分类（留步骤 3、4）。

### 步骤 3｜回写原文　`methods_backlink`

- 纯 PMID 驱动：按 `methods_ai_result` 逐篇定位源论文笔记（在 `待分析文献文件夹`）。
- 把 M&M 章节正文替换为 `[[方法名]]` 双链列表（总是用本次结果重新替换，支持反复重跑）。
- 同时写入 frontmatter `研究方法` 属性（双链列表）。
- 未找到笔记 / 未定位到 M&M 章节 → 跳过并告警。

---

## 三、第二趟：补定义 + 研究目的 + 大分类

### 步骤 4a｜定义拼接　`methods_def_assemble`

- 扫方法辞典中**定义列为空**的方法 + 大分类释义地图 → 拼「方法定义指令 + 待补清单」→ 剪贴板。
- 待补 0 个时提示无需处理。
- 贴给 AI，AI 输出四列表（具体方法 | 定义 | 研究目的 | 大分类）到 `methods_def_ai_result`。

### 步骤 4b｜定义回填　`methods_def_apply`（**流程最后一步**）

- 解析第二趟四列表：
    - 回填辞典（定义 / 研究目的 / 大分类三列）。
    - 写具体方法笔记的 `大分类` / `研究目的` 属性。
    - 建大分类笔记（→ `methods_category_notes_dir`，双链索引归属的具体方法）。
    - 更新「已参考」（PMID 取自第一趟 `methods_ai_result`）——这是 M&M 流程的防重复闸门，下次拼接扫到即跳过。

---

## 四、典型操作顺序

```
第一趟：拼接① → (贴AI，人工审核解除[待审]) → 笔记创建分发② → 回写原文③
第二趟：定义拼接④a → (贴AI) → 定义回填④b
```

> 设计要点：
> 
> - 方法名/变体（第一趟）与定义/分类（第二趟）分两趟，因为分类需要先看到全部方法才能准确归大类。
> - `[待审]` 是新方法/新变体的人工闸门：AI 标记 → 你审核解除 → 脚本才落地。
> - 「已参考」在最后一步（定义回填）才写，确保一篇论文走完整两趟才算「已处理」，中途重跑不会漏。
> - 回写原文（步骤3）的双链指向具体方法笔记，YAML 研究方法属性供 Obsidian Base 按方法聚合检索。
