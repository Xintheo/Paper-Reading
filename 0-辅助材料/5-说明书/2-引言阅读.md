# 引言工作流说明书

引言这条线把一篇论文的引言，拆成两层产物：

- **引言分析层**——逻辑链笔记 + 元素笔记（句子级、元素标签、论证脉络）；
- **知识点层**——把引言里的知识沉淀成跨文体共享的「知识点笔记」（关键词 → 知识点 → 笔记名三层归纳）。

讨论、综述将来也汇入同一个知识点库，但前半段分析各走各的，后半段（知识点的提名/创建/命名/回填）共用本说明书描述的这一套。

---

## 一、三层数据模型（先理解，再操作）

- **关键词**：碎片、原子级，一段可以很多。做笔记的属性标签。同义/中英写法要归一（eQTL 不再并列“顺式表达数量性状位点”）。
- **知识点**：把关键词归纳后的系统概念（意群），一段顶多 2–3 个。
- **笔记名**：知识点的产物——一个知识点就用它，几个就连接或抽象命名。

辞典用**两张表**承载，单一真相源、防膨胀：

- **知识点词表**（`知识点 | 关键词`）：规范化中枢。关键词只在这里存一份，每个知识点名下挂它的全部关键词。
- **确认笔记**（三分类下 `确定笔记名称 | 知识点`）：身份登记，每篇已确认笔记包含哪些知识点。

关键设计：**创建+分发不写任何语义属性，关键词/知识点/分类全部等第二趟「名称回填」确定后才写进笔记 YAML。**

---

## 二、操作步骤（九步，含三次 AI 回合）

> 凡“拼接”步：脚本生成 prompt 并复制到剪贴板 → 你贴给 AI → 把 AI 回复**粘贴进对应中转文件** → 再点下一步。中转文件没更新就跑下一步＝解析 0 篇。

### A. 引言分析层

1. **引言拼接**（`intro_assemble`，有「手选模式」） 扫描待分析文献的引言 → 按段分句 → 拼“引言分析指令 + 引言辞典 + 元素辞典” → 剪贴板。 → 贴给 AI，结果粘进 **引言分析中转**（键 `introduction_ai_result`，在 `3-中转站`，与摘要分析共用同一个「AI结果中转」）。
    
2. **笔记创建+分发**（`intro_create_distribute`） 解析引言分析结果 → 在 `2-引言笔记` 建逻辑链笔记、在 `0-元素笔记` 建元素笔记 → 分发实例与例句 → 更新引言辞典、元素辞典、已参考论文。
    

### B. 知识点层（核心）

3. **知识点拼接（提名·第一趟·粗筛）**（`knowledge_assemble`） 读引言分析结果 + 知识点辞典（知识点词表 + 确认笔记）+ 元素辞典 → 拼“知识点提名指令” → 剪贴板。 AI 每段输出一行 `段号 | 推荐笔记名 | 关键词 | 分类`，每篇用 `## 文献N (PMID: 数字)` 块头。 → 结果粘进 **知识点提名中转**（键 `knowledge_ai_result`）。
    
4. **知识点笔记+分发**（`knowledge_create_distribute`） 解析提名结果（须有 PMID 块头）→ 一段一笔记，在 `0-知识点笔记` 建笔记（frontmatter 只有 `待处理: true`，**不写语义属性**）→ 把引言原文按文体分区写进正文（见第四节）→ 新笔记的“原始关键词”写进辞典「修改中转」。 复用机制：推荐笔记名若已在「确认笔记」→ 直接复用、不进中转；否则进中转待命名。
    
5. **命名拼接（细筛·第二趟）**（`kp_def_assemble`） 取辞典「修改中转」的原始关键词 + 当前「知识点词表」+ 知识点命名指令 → 拼四列待命名表 → 剪贴板。 → AI 输出 `原始关键词 | 归一关键词 | 知识点 | 确定笔记名称`，粘进 **命名中转**（键 `knowledge_definition_result`）。
    
6. **名称回填**（`kp_def_apply`） 解析命名结果四列 → ① 重命名笔记文件 + **全库单遍改双链**（`[[旧名]]`/`[[旧名|别名]]`/`[[旧名#标题]]`/`![[旧名]]`，只写改动）→ ② 写笔记 YAML `关键词`(归一) + `知识点` → ③ 并入「知识点词表」→ ④ 写「确认笔记 确定笔记名称|知识点」→ ⑤ 清空「修改中转」。
    

下一轮第 3 步会看到新确认的知识点与笔记名，据此复用——增量打磨，逐轮收敛。

## 三、配置键速查

### 文件键（config.json 显式指定，放对文件夹即可）

|配置键|所在文件夹|用途|
|---|---|---|
|`introduction_prompt_template`|1-AI指令|引言分析指令|
|`knowledge_prompt_template`|1-AI指令|知识点提名指令（第一趟）|
|`knowledge_definition_template`|1-AI指令|知识点命名指令（第二趟）|
|`introduction_dictionary_file`|2-辞典|引言辞典（逻辑链/元素）|
|`knowledge_dictionary_file`|2-辞典|知识点辞典（两表：词表 + 确认笔记）|
|`element_dictionary_file`|2-辞典|元素辞典|
|`introduction_ai_result`|3-中转站|引言分析 AI 结果（与摘要共用 AI结果中转）|
|`knowledge_ai_result`|3-中转站|提名结果（第一趟）|
|`knowledge_definition_result`|3-中转站|命名结果（第二趟）|

### 文件夹键（由项目根 + 相对路径自动派生，键缺失/为空时自动填，不覆盖已有值）

|配置键|相对路径|角色|
|---|---|---|
|`待分析文献文件夹`|1-文献输入/1-文献原文|输入论文|
|`element_notes_dir`|2-文献摘抄/0-元素笔记|元素笔记（跨文体共享）|
|`knowledge_notes_dir`|2-文献摘抄/0-知识点笔记|知识点笔记（跨文体共享，单键）|
|`introduction_notes_dir`|2-文献摘抄/2-引言笔记|引言逻辑链笔记（已拍平，无子夹）|

> 自动连接：config.json 须位于 `项目根/0-辅助材料/1-工作流文件/`，脚本据此反推项目根，再拼出各目录。新库重置只需建好空文件夹，目录键自动接上。

## 四、笔记产物形态

**知识点笔记 YAML**（创建时仅 `待处理: true`；下列属性在“名称回填”后才出现）：

```
---
待处理: true
关键词:
  - 急性肾损伤
  - 肾缺血再灌注损伤
知识点:
  - 急性肾损伤
  - 肾缺血再灌注损伤
---
```

**正文按文体分区**（同一篇笔记可累积引言/综述/讨论三个区，互不串味）：

```
# 整理
# 未整理
## 引言
### 逻辑链
- (PMID: 41905213): [文献现状引出] → [研究目的]
### 具体知识点
- (PMID: 41905213): [文献现状引出] 急性肾损伤是常见危重症。
- (PMID: 41905213): [研究目的] 缺血再灌注是主要病因之一。
```

`# 整理` 区是人工整理产物，脚本永不改动；分发只往 `# 未整理` 追加、去重保序。

## 五、常见问题

- **解析 0 篇**：多半是该步的中转文件没更新（AI 回合没接上），或提名结果缺 `## 文献N (PMID: 数字)` 块头——块头是脚本定位文献、把段落对回引言的唯一依据，不能省。
- **关键词没归一/笔记没属性**：属性在“名称回填”后才写；只跑到“创建+分发”时笔记本就没有关键词/知识点，正常。
- **重命名后双链断没断**：不会断。脚本在回填时全库单遍重写所有指向旧名的双链（只写改动的文件）。
- **改了脚本/指令后“重置新库”没变化**：需要 ① 替换本地脚本 ② 重建前端 ③ 把辞典/两份指令推到 GitHub 仓库（或手动放进库）——否则重置又从仓库拉旧模板。
- **复用判断在哪层**：第一趟按“推荐笔记名是否已在确认笔记”粗判（命中即复用、不进中转）；精确的知识点归纳在第二趟。确认笔记里的知识点 + 词表，是喂给第一趟做识别的词表。
