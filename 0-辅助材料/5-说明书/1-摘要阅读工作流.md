# 摘要线 · 完整工作流总结

> 论文阅读流水线(Tauri v2 + Obsidian)的「摘要→笔记」子系统。 与引言「知识点线」并列、但架构不同:摘要线建**逻辑链笔记**和**元素笔记**两种。 主脚本:abstract_assemble.py(拼接) + abstract_create_distribute.py(建笔记+分发)。
> 
> 说明:本总结的脚本流程依据实际代码;AI 指令与元素辞典细节部分依据记忆碎片(19元素、结果凝练vs核心论断边界),标注为「据记忆」。

## 一、整体流程

```
① 拼接   abstract_assemble.py
   扫描文件夹(批量:true、有PMID、未参考) → 抽取 Abstract
   → 按三级标题(### Background/Methods…)切段,标题归一化为中文
   → 每段分句、编号 → 拼接 + 复制剪贴板
[AI 分析:每篇摘要 → 逻辑链(元素流向) + 逐句元素标注(19元素闭集)]
② 建笔记 + ③ 分发   abstract_create_distribute.py
   建逻辑链笔记 / 元素笔记(已存在则补并集)
   分发:逻辑链流向写进逻辑链笔记;逐句按元素写进元素笔记
   更新摘要辞典 / 元素辞典
```

## 二、两种笔记

### 逻辑链笔记(logic chain note)

- **一条逻辑链 = 一种"元素流向模式"**(如 [背景][问题][方法][结果] 的某种排布)
- 笔记 YAML:`章节(摘要) / 定义 / 逻辑链形式(一段式/分段式,并集) / 分段内容(背景/方法/结果…,并集) / 待处理`
- 正文「实例」区:每篇文献一条实例 `- (PMID: x): [元素1] → [元素2] → [元素3] …`
- 同名逻辑链跨论文:形式/分段内容取**并集**;实例按整行判重(`instance_line in existing` 跳过)

### 元素笔记(element note)

- **19 个元素的闭集**(摘要描述视角,如 背景/目的/方法/结果/结论… 据记忆)
- 笔记 YAML:`章节(摘要) / 笔记类型(元素) / 功能描述 / 待处理`
- 正文「## 摘要」子区:收集所有标注为该元素的句子,按 PMID 分组 `### PMID: x` 下挂 `- 句子`
- **PMID 查重只在「## 摘要」子区内**(不与同笔记的「## 引言」等其它章节撞车)

## 三、拼接脚本关键处理(abstract_assemble.py)

- **筛选**:frontmatter `批量:true` + 有 PMID + 不在「已参考」→ 才处理
- **抽取 Abstract**:正文匹配 abstract 标题行 → 到下一个 `##` 为止
- **三级标题切段 + 归一化**:`### Background/Methods/Results…` → 剥序号 → 查 section_map 映射为中文标准名(背景/方法/结果…)。一段式 → `_全文`;分段式 → 各段分别处理
- **分句**:过滤 Keywords 行;保护引用标记 `[n](url)` 和 URL(占位后还原);按 。!？. 切句;逐句编号
- **输出**:分段式带 `### 中文标题` + 编号句;一段式直接编号句

---

## 四、建笔记 + 分发关键处理(abstract_create_distribute.py)

- **建逻辑链笔记**(create_logic_chain_notes):新建写 frontmatter + 「实例」骨架;已存在 → ensure_chain_meta_in_frontmatter 补并集(形式/分段),不顶替正文
- **建元素笔记**(create_element_notes):19 元素;已存在 → ensure_section_in_frontmatter 补「摘要」章节
- **分发逻辑链**(distribute_to_chain_notes):写元素流向实例行,占位符 `（待 distribute 分发后填充）` 首次替换、之后追加;整行判重
- **分发元素**(distribute_to_element_notes):句子按元素归集 → 按 PMID 分块写「## 摘要」子区;PMID 子区内判重;无「## 摘要」子区则在「# 未整理」末尾新建
- **辞典更新**:update_abstract_dictionary(逻辑链)/ update_element_dictionary(元素)/ update_referenced(已参考 PMID)
