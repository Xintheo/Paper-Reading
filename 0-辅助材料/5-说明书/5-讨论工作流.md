# 讨论工作流说明书

> Obsidian 文献阅读流水线 · 讨论(Discussion)章节处理 原则：AI 负责判断，脚本负责搬运。每层一个"拼接→AI→回写"循环。

---

## 一、总览

讨论工作流把一篇论文的讨论章节，逐层拆解成三种可复用的结构化产物：

|层|名称|产物|回答的问题|
|---|---|---|---|
|阶段一|**结构层**|位置笔记 + 功能笔记 + 功能链/位置链|这段讨论在**哪个位置**、起**什么功能**|
|阶段二|**元素层**|元素笔记(按句原文) + 元素链|每句话用了**什么写作元素**|
|阶段三|**知识点层**|原文献「## 讨论」知识点表 + 汇总大表|这篇讨论沉淀了**哪些具体知识点**|

三层互相独立、依次推进。每层都是：**拼接脚本**(读上游+配指令/辞典→剪贴板) → **AI**(网页模型判断) → **回写脚本**(解析AI输出→落笔记)。

---

## 二、运行顺序

```
阶段一  ① discussion_assemble(结构拼接)
        → AI 填四列表(段号/原文/位置/功能)
        ② discussion_structure_create(结构创建分发)

阶段二  ③ discussion_element_assemble(元素拼接)
        → AI 逐句贴元素标签
        ④ discussion_element_distribute(元素回写)

阶段三  ⑤ discussion_knowledge_assemble(知识点表拼接)
        → AI 生成中英对照知识点表
        ⑥ discussion_knowledge_inject(知识点表回写)
```

三个阶段建议**按序跑完一篇再跑下一篇**；阶段之间不强制耦合，但阶段二、三都依赖阶段一产出的"四列表中转站"。

---

## 三、阶段一 · 结构层(位置 + 功能)

### 步骤① discussion_assemble —— 结构拼接

- **读**：待分析文献文件夹里 `批量: true` 的论文笔记，按讨论标题变体(Discussion/DISCUSSION/Discussion and Conclusions/General Discussion/4. Discussion 等)定位讨论章节
- **做**：抽出讨论各段原文，预填四列表骨架 `| 段落 | 段落原文 | 讨论位置 | 段落功能 |`(后两列留空待 AI 填)，拼接讨论叙事辞典 → 剪贴板
- **跳过**：已在讨论辞典「已参考论文」登记的 PMID

### AI：填四列表

- **讨论位置**(3 个固定)：开篇重申 / 主线展开 / 收束总结
- **段落功能**(14 个固定)：背景综述 / 发现重申 / 发现概述 / 同向引证 / 异向辩驳 / 异向求和 / 发现阐释 / 机制串联 / 假说提出 / 局限承认 / 优势声明 / 意义延伸 / 临床转化建议 / 展望收束
- **判据**：辞典 v3.0.1，3 判据簇(簇A位置切换 / 簇B推断类三分 / 簇C两独立细则)；推断类(发现阐释/机制串联/假说提出)靠"区分锚点"切分

### 步骤② discussion_structure_create —— 结构创建分发

解析四列表 → 三件事：

1. **建功能笔记**：每个出现的功能建一个笔记(`分析层级: 段落功能`)
2. **建位置笔记**：固定 3 个位置笔记(`分析层级: 段落位置`)
3. **写位置链**：位置笔记「未整理」区写功能链 `- (PMID) [[功能A]]→[[功能B]]`(按段号序，幂等)

并更新**讨论叙事辞典**「已参考论文·讨论」区。

**中转站**：`discussion_ai_result`(四列表，供阶段二、三复用)

---

## 四、阶段二 · 元素层(句子元素)

### 步骤③ discussion_element_assemble —— 元素拼接

- **读**：阶段一中转站(`discussion_ai_result`)，按段取原文+功能(脚本不拆句)
- **做**：组织成 `### 第N段 (功能)` + 整段原文，拼接元素标注指令(指令B) + 清理后的元素辞典 → 剪贴板
- 元素辞典拼接前会剥掉版本说明/速查索引/已参考论文(只留 67 个元素定义)

### AI：逐句贴元素标签

- AI 负责断句，逐句贴**元素中文全名**标签(如 `[机制递进]`、`[支持性证据]`，NOT 编号)
- 输出格式：`### 第N段 (功能) → - [元素全名] 句子`

### 步骤④ discussion_element_distribute —— 元素回写

解析元素结果 → 两个去向：

1. **功能笔记** ← 元素逻辑链 `- (PMID 第N段) [元素A]→[元素B]`(进未整理区，幂等)
2. **元素笔记** ← 按句原文(`## 讨论 → ### PMID` 区，YAML `章节: -讨论`，跨章节共用追加不覆盖)

并更新**元素辞典**「已参考论文·讨论」区(与摘要/引言工作流一致)。

**中转站**：`discussion_element_output`

---

## 五、阶段三 · 知识点层(知识点表)

### 步骤⑤ discussion_knowledge_assemble —— 知识点表拼接

- **读**：阶段一中转站(`discussion_ai_result`)，**只取段号 + 原文**(剥掉骨架/判定说明/自检/YAML/位置功能列)
- **做**：组织成 `### 第N段` + 原文，拼接知识点表指令 → 剪贴板

### AI：生成中英对照知识点表(4 列)

- **不依赖句子标签**，靠**语义 + 引文**判断每句三类：
    - **A 类**(本文论点/知识点)→ 填「本文结果」两列
    - **B 类**(参考文献支撑，含引文)→ 填「参考文献结论」两列
    - **C 类**(纯推断/机制/局限/意义/展望)→ 丢弃
- **A/B 判别(内化)**："本文告诉你一个背景事实"=A；"本文转告你别人研究发现了什么"=B。看叙事主体，不看有无引文
- **引文链接嵌入式**：链接留在句子原位(中英文句都嵌)，便于句子+链接一起分析、后续溯源
- 一句一行；多引文合并，链接留原位

### 步骤⑥ discussion_knowledge_inject —— 知识点表回写

解析知识点表 → 两个去向：

1. **原文献笔记**(4 列)：
    - 按 YAML `PMID:` 定位论文笔记
    - **删除原讨论章节**(英文变体标题+正文整段删——原文已榨干，正文不留)
    - 在 `## 结果` 之后**新建 `## 讨论`**，只放知识点表
    - 效果：不同期刊统一收束为 **摘要 / 引言 / 材料和方法 / 结果 / 讨论** 中文结构
2. **汇总 md「讨论表格总结」**(5 列)：
    - 最左加 **PMID 列**自动填入，连续大表(不分整理/未整理、无标题分隔)
    - 没有则创建(带表头)、有则增量追加
    - **按 PMID 去重**：已有整篇跳过(幂等)
    - 每行自带 PMID + 嵌入链接，便于后续选材溯源

## 六、脚本清单

|脚本|阶段|角色|
|---|---|---|
|`discussion_assemble.py`|一|结构拼接|
|`discussion_parse.py`|一|解析四列表(严格锚定表头、排骨架污染)|
|`discussion_structure_create.py`|一|建位置/功能笔记 + 位置链 + 更新讨论辞典已参考|
|`discussion_element_assemble.py`|二|元素拼接(读中转站+指令B+清理元素辞典)|
|`discussion_element_distribute.py`|二|元素回写(功能链+元素笔记) + 更新元素辞典已参考|
|`discussion_knowledge_assemble.py`|三|知识点表拼接(只取段号+原文)|
|`discussion_knowledge_inject.py`|三|知识点表回写(原文献删建+汇总md)|
|`clean_bad_notes.py`|—|一次性清理早期 bug 误建的污染笔记，用完即删，不进工作流、无按钮|

> `discussion_create_notes.py` / `discussion_distribute.py` 为早期版本，现行流程以上表为准。

runner.py dispatch(6 步)： `discussion_assemble` / `discussion_structure_create` / `discussion_element_assemble` / `discussion_element_distribute` / `discussion_knowledge_assemble` / `discussion_knowledge_inject`

## 八、笔记结构速查

**位置笔记**(3 个)：`分析层级: 段落位置`，未整理区存功能链

```
- (PMID) [[发现概述]]→[[发现阐释]]→[[机制串联]]
```

**功能笔记**：`分析层级: 段落功能`，未整理区存元素链

```
- (PMID 第6段) [机制递进]→[结果验证呼应]→[文献对比]
```

**元素笔记**：`章节: -讨论`，`## 讨论 → ### PMID` 区存按句原文(跨章节共用)

**原文献笔记**(归一化后)：

```
## 摘要 / ## 引言 / ## 材料和方法 / ## 结果 / ## 讨论(只放知识点表)
```

**汇总 md「讨论表格总结」**：5 列连续大表

```
| PMID | 本文结果(中文) | 参考文献结论(中文) | 本文结果(原文) | 参考文献结论(原文) |
```

## 九、注意事项

- **文件配套全换**：runner.py + 各 discussion_*.py + 辞典/指令需同步更新，只换一部分会出现旧行为
- **辞典「标题名称」区说明文字**用 `>` 引用行，否则会污染讨论标题变体表
- **真实 vault 旧残留**：早期测试若残留「## 讨论知识点表」旧区，新逻辑(删讨论变体+建 ## 讨论)不自动清理，需手动删
- **clean_bad_notes.py**：仅清理早期 parse bug 的污染笔记，用完即删
