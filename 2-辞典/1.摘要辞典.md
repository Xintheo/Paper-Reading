# 摘要写作辞典 v3.2

段落级叙事推进模式，名称归一化。

本辞典只定义逻辑链的**名称、定义与边界**。标注规则、元素序列的具体标注方法等"如何使用"的内容，由配套指令文档承接。

逻辑链层已**焊死**：每个结构类型/段落唯一对应一个固定名称（见下表），标注时按结构直接归入，组内无选择、无需 AI 判断。名称仅为各笔记的固定标签，其下积累元素序列供写作聚合。

**归类**：一段式整体、分段式各段，按「逻辑链」区的固定映射归入对应名称即可。叙事推进的具体形状由元素序列承载，名称层不细分。元素序列由元素辞典（摘要区）提供、忠实记录本文实际排列，**不参与名称选择**。本辞典不嵌入元素序列与元素 ID——元素清单在元素辞典独立维护。

背景类逻辑链中的"现状"为通用口径，泛指疾病背景（流行病学/负担/机制）或物质/干预背景（属性/已知功能/现有疗法），不限于疾病流行病学。

## 版本变更

> 本区为维护沿革，仅供人工查阅；脚本喂 AI 前会自动剥离，不影响标注。

- **v3.1 → v3.2**：逻辑链层焊死——每个结构类型/段落由"多选一"压成"唯一归入一个固定名称"（一段式→顺序铺陈，背景→现状引题，目的→目的陈述，方法→方法铺排，结果→结果陈列，结论→收束性陈述）。删去结论先行、径取问题、策略统领、终点汇报、意义展望及各「与X区分」边界——组内不再有选择，AI 在本层无需语义判断，从而消除逻辑链横跳。区分力全部由元素辞典摘要区的元素序列承载。名称仅作笔记固定标签。
    
- **v3.0 → v3.1**：清理与元素辞典 v4 摘要区不一致的残留——删去「结果陈列」词条内对已废结果元素（结果递进/平铺/筛漏、对比关系/动态趋势等）的引用，结果区元素以元素辞典摘要区为准（单点呈报/多点综述/呼应印证/机制解读）；正文与「后续积累方式」统一为 11 条（原残留"15 条"旧数已订正）；移除"如何标注/积累流程"等属配套指令职责的描述，辞典只留逻辑链定义与边界；正文判据不再绑定具体版本号。
    
- **v2.9 → v3.0**：逻辑链由 15 条收束至 11 条。结果类 4 条（结果递进/结果平铺/结果筛漏）合并为「结果陈列」（保留「终点汇报」）——结果形状的区分力移到元素层；方法类「方法筛漏」并入「方法铺排」；一段式「交织推进」并入「顺序铺陈」。

## 标题名称

归一化识别摘要二级标题的各种写法，用于定位 ## Abstract 起始行。格式：归一化名称: 变体1, 变体2, ... 匹配时自动剥离序号（如 1. / 1.1 / (1) / 一、等）。

摘要: Abstract, ABSTRACT, abstract, Summary, SUMMARY, 中文摘要, 【摘要】

## 分段标题归一化

背景: Background, Introduction 
目的: Objective, Aim, Purpose 
方法: Methods, Materials and Methods, Patients and Methods, Methodology 
结果: Results, Findings, Outcomes 
结论: Conclusion, Conclusions, Summary, Discussion

## 逻辑链（焊死：每个结构类型 / 段落唯一归入一个名称，无组内选择）

每个结构类型（一段式）或段落（背景/目的/方法/结果/结论）**只对应一个固定名称**，标注时该结构/段落直接归入对应名称，**不在组内做任何选择**。叙事推进的具体形状（正序/倒置、有无统领句、是否分层汇报等）全部由元素序列承载、在元素辞典摘要区记录，名称层一律不再细分。下游写作时按这几个固定笔记聚合元素序列。

| 结构类型 / 段落 | 唯一归入名称 |
| --------- | ------ |
| 一段式       | 顺序铺陈   |
| 背景        | 现状引题   |
| 目的        | 目的陈述   |
| 方法        | 方法铺排   |
| 结果        | 结果陈列   |
| 结论        | 收束性陈述  |

- **一段式** → 顺序铺陈
- **分段式** → 各段按上表归入：背景→现状引题、目的→目的陈述、方法→方法铺排、结果→结果陈列、结论→收束性陈述。

名称仅为各笔记的固定标签，本身不含判断；它叫什么不重要，重要的是其下积累的元素序列。结构类型（一段式/分段式）由有无三级标题决定，分段段落名由脚本归一化——故本层 AI 无需做语义判断，按结构直接归入即可。
